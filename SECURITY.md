# AirIsland — Security & Privacy Audit

This document lists **everything** AirIsland can do with your Mac, so you can verify it yourself rather than trusting a claim.

- **No prebuilt binaries.** The zip contains only `.swift`, `.sh`, `.command`, `.plist` and `.md` files. `AirIsland.app` does not exist in the download — it is compiled on your machine by `build.sh` / `Install AirIsland.command` using Apple's `swiftc`. There is no hidden compiled payload to scan for.
- **~7,300 lines** of readable Swift, no obfuscation (no `base64`, no hex blobs, no generated payloads).
- **Not notarized.** The app is ad-hoc signed (`codesign -s -`). That is why macOS shows "unidentified developer". This is a signature/trust warning, not a malware detection. See the README for the one-time `xattr` fix.

---

## 1. Network activity — complete list

| Destination | When | What is sent | What comes back |
| :--- | :--- | :--- | :--- |
| `https://lrclib.net/api/get`<br>`https://lrclib.net/api/search` | Only when you open the **Lyrics** view for a track | Track title, artist, album, duration (URL query) + `User-Agent: AirIsland/1.0` | Synced/plain lyrics text |
| Spotify artwork CDN URL | Only if Spotify is running and artwork is missing | Nothing (plain GET) | Album image |
| Apple Music artwork | Only if Music is running | **No network request** — artwork bytes are read locally via AppleScript | — |

No other hostnames appear anywhere in the source. There is **no analytics, telemetry, crash reporting, advertising or update-checking code** — grepping for `analytics|telemetry|firebase|sentry|amplitude|mixpanel|upload|beacon` returns nothing.

All requests are plain `URLSession` GETs with an 8-second timeout. No custom headers carry identifiers, no cookies, no device IDs.

## 2. Apple Events / AppleScript

Only two target apps are ever scripted: **Music** and **Spotify**, and only for playback:

```
player state is playing   ·   name of current track   ·   artist / album / duration
player position           ·   playpause / next track / previous track / set player position
artwork url / raw data of artwork
```

No `do shell script`, no `osascript` subprocess, no `tell application "Finder"` or any other app. The app never spawns a process (`Process`/`NSTask`/`system`/`popen` do not appear in the source). `Info.plist` declares `NSAppleEventsUsageDescription`, so macOS asks your permission the first time and you can revoke it in **System Preferences → Security & Privacy → Automation**.

## 3. Input monitoring

| Monitor | Scope | What it can see |
| :--- | :--- | :--- |
| Global mouse monitor | Whole system | Only that a click happened + the cursor location, used to collapse the island when you click outside it. **Requires no permission.** |
| Local mouse monitor | This app's own window | Pointer moves inside the island (hover + cursor sheen) |
| Local key monitor | This app's own window, only while expanded | Only `Esc` (keyCode 53) — the handler returns every other key untouched |

There is **no global keyboard monitoring**, no keylogging, no `CGEventTap`, no screen capture, no accessibility API usage. AirIsland does not ask for Accessibility, Screen Recording, Full Disk Access, or Input Monitoring permission.

## 4. Clipboard

Clipboard History is an advertised feature, so the app does read `NSPasteboard.general` — read this and decide:

- It polls `changeCount` (a cheap counter, no polling of contents) and reads text only when the clipboard actually changed.
- Entries marked concealed/transient/auto-generated by password managers (`org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType`) are **skipped**, so copied passwords are not stored.
- History is an **in-memory array only** — it is never written to disk and is lost when the app quits.
- It is never transmitted. The only outbound traffic is the lyric lookup in §1.

## 5. Files written to disk — complete list

| Path | Purpose | Removable |
| :--- | :--- | :--- |
| `~/Library/Preferences/com.airisland.app.plist` | Your toggles via `UserDefaults` (placement, theme, hover, toasts) | Yes |
| `~/Library/LaunchAgents/com.airisland.app.plist` | Only if you enable **Launch at login**. Contains one `ProgramArguments` entry pointing at AirIsland's own executable | Deleted when you turn the toggle off |
| `/Applications/AirIsland.app` | The installed app (created by the installer, not by the app) | Yes |

Nothing is written to `/Library`, `/System`, `~/Documents`, or your home folder root. **Nothing in the project uses `sudo`.**

## 6. Installer scripts

`Install AirIsland.command` and `build.sh`:

- `chmod +x` on the project's own files
- `swiftc` compile, `codesign --sign -` (ad-hoc), `iconutil` for the icon
- `rm -rf /Applications/AirIsland.app` before copying the freshly built bundle (only that one exact path)
- `xattr -cr` on the installed app to clear the quarantine flag
- `open /Applications/AirIsland.app`
- `pkill -x AirIsland` before reinstalling

No `curl`, no `wget`, no downloads, no `launchctl load`, no background daemons beyond the optional LaunchAgent above.

## Verify it yourself

```bash
# 1. Confirm the download contains no binaries
unzip -l AirIsland.zip | grep -vE '\.(swift|md|plist|sh|command)$'

# 2. Read the only two network call sites
grep -n "URLSession\|https://" AirIsland/Sources/AirIsland/*.swift

# 3. Confirm no process spawning
grep -rn "Process(\|NSTask\|osascript\|do shell script" AirIsland/Sources/AirIsland/

# 4. Watch what it actually dials (needs Little Snitch or LuLu), or:
sudo lsof -i -P -n | grep AirIsland

# 5. Build from source and run your own copy — the binary is produced by your machine
cd AirIsland && ./build.sh app
```

If you would rather not run a script at all, build it in Xcode instead: `open Package.swift` → ⌘R.
